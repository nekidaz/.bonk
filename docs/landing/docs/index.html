BONK / DOCUMENTATION

From first request to shared workflow.

Open a local folder, send an API call, and save the request as a file. These guides cover the desktop app, CLI, and MCP server.

Get started ↓Download Bonk ↗

01 / START HERE

Your first request

Download Bonk for macOS, Windows, or Linux. On Apple Silicon macOS you can also install it with Homebrew: 

brew install --cask nekidaz/tap/bonk
  1. Open a folder. Any empty directory can become a workspace.
  2. Create an HTTP request. Enter an address such as http://localhost:8080/health.
  3. Send it. Read the status, body, headers, and timing in the response pane.
  4. Save it. Press ⌘S on macOS or Ctrl+S on Windows and Linux, then choose a folder.

Editing and organizing a workspace works offline. Sending requests and checking for updates use the network.

02 / LOCAL WORKSPACE

Collections are folders. Requests are files.

A saved request is a readable .bonk.json file. Bonk uses the directory as the source of truth, so the workspace can live beside your code and be reviewed in Git. 

payments-api/
├── payments/
│   ├── list-payments.bonk.json
│   └── create-payment.bonk.json
└── grpc/
    └── say-hello.bonk.json

A minimal HTTP request looks like this:

{
  "name": "List payments",
  "protocol": "http",
  "request": {
    "method": "GET",
    "url": "{{baseUrl}}/v1/payments",
    "headers": {}
  }
}

Folder auth can be saved in .folder.bonk.json. App preferences and history live separately in the OS application-data directory. Review request files before committing them if you entered credentials directly.

03 / PROTOCOLS

HTTP and gRPC in one app

HTTP

Set query parameters, headers, auth, and a body. Bonk supports JSON, text, forms, multipart, binary data, and GraphQL. The response view includes formatted content, cookies, status, size, and timing. You can search JSON responses and use JSONPath filters.

gRPC

Connect to a server with reflection or load local .proto files. Pick a service and method, edit a message template, and invoke it. Bonk also supports metadata, deadlines, TLS/mTLS, and streaming calls in the desktop app.

04 / REUSE

Variables, environments, and tests

Create a named environment with baseUrl = http://localhost:8080, then use {{baseUrl}}/health in a request. Globals and environment variables can be edited in the app. Secret variables use the OS keychain when available.

Use Scripts → Tests to add an assertion after a response:

pm.test("Service is healthy", () => {
  pm.expect(pm.response).to.have.status(200);
});

Send the request again and open the Tests response tab. Pre-request scripts can prepare values before a call; response scripts can inspect results and update variables.

Scripts run in a sandbox with supported pm.* helpers. Bonk does not implement every Postman script API.

05 / REPEAT

Run a collection in the app or CI

In Runner, select requests, put them in order, choose an environment, and set iterations, CSV/JSON data, delays, and stop-on-failure behavior. Inspect results and export a report. You can save a portable workspace scenario in .bonk/scenarios.json.

The Bonk CLI uses the same request engine. Install it separately, then run a workspace or a saved scenario: 

brew install nekidaz/tap/bonk
bonk run --workspace ./api
BONK_VAR_TOKEN="$TOKEN" bonk run --workspace ./api --scenario smoke --junit report.xml

Use BONK_VAR_* for secrets in CI. See the CLI reference for flags, network settings, exit codes, and scenario behavior.

06 / AI TOOLS

Connect a client through MCP

Bonk ships a headless MCP server. Compatible clients can browse saved requests, edit the workspace, explore gRPC schemas, and execute API calls. The desktop app does not need to stay open for a configured headless server.

  1. Open the workspace the client should use.
  2. Go to Settings → AI / MCP.
  3. Choose whether to allow workspace edits and API calls. Add a target-host allowlist if needed.
  4. Select Install for all clients, then restart the configured apps.

The installer supports Claude Desktop, Claude Code, and ChatGPT/Codex local clients. For manual STDIO or Streamable HTTP setup, variables, redaction, and permission details, read the MCP reference.

ChatGPT web does not read your local MCP configuration. A local desktop client or separately hosted connection is required.

07 / BRING YOUR WORK

Import existing requests

Import OpenAPI/Swagger, Postman, Insomnia, HAR, or cURL through the desktop app. You can provide a file, link, paste, or drop and preview the result before importing. Re-import can update a collection while preserving your edits.

Bonk can export collections and generate language-specific snippets for individual requests. The CLI can import a Bonk workspace export; other import formats use the desktop app.

Need implementation details? Read the project README, CLI reference, or MCP reference.
